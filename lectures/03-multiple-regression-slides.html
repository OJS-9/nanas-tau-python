המודל

\[ Y_i = \beta_0 + \beta_1 x_i + \varepsilon_i \qquad i = 1, \dots, n \]

  • \(\beta_0\) הוא החותך (intercept) ו-\(\beta_1\) הוא השיפוע (slope): בכמה משתנה התוחלת של \(Y\) כש-\(x\) עולה ביחידה אחת
  • \(E(Y \mid x) = \beta_0 + \beta_1 x\) ו-\(V(Y \mid x) = \sigma^2\)

ההנחות על השגיאות \(\varepsilon_i\):

  1. לינאריות: התוחלת של \(Y\) היא פונקציה לינארית של \(x\)
  2. אי-תלות: השגיאות בלתי תלויות זו בזו
  3. שונות קבועה (homoscedasticity): אותה \(\sigma^2\) לכל ערך של \(x\)
  4. נורמליות: \(\varepsilon_i \sim N(0, \sigma^2)\). נדרשת למבחנים ולרווחי הסמך, לא לאמידה עצמה

שיטת הריבועים הפחותים (Least squares)

מחפשים את הקו שממזער את סכום ריבועי הסטיות האנכיות:

\[ L(\beta_0, \beta_1) = \sum_{i=1}^{n} \left(y_i - \beta_0 - \beta_1 x_i\right)^2 \]

גוזרים לפי \(\beta_0\) ולפי \(\beta_1\) ומשווים לאפס (משוואות נורמליות), ומקבלים:

\[ \hat\beta_1 = \frac{S_{xy}}{S_{xx}} \qquad \hat\beta_0 = \bar y - \hat\beta_1 \bar x \]

\[ S_{xx} = \sum_{i=1}^{n} (x_i - \bar x)^2 = \sum x_i^2 - n\bar x^2 \qquad S_{xy} = \sum_{i=1}^{n} (x_i - \bar x)(y_i - \bar y) = \sum x_i y_i - n \bar x \bar y \]

\[ \hat\beta_1 = \frac{62.80}{44.99} = 1.396 \qquad \hat\beta_0 = 18.81 - 1.396 \cdot 13.61 = -0.188 \]

\[ SS_R = \hat\beta_1 S_{xy} = 87.66 \qquad SS_E = S_{yy} - SS_R = 97.91 - 87.66 = 10.25 \qquad \hat\sigma^2 = \frac{SS_E}{n-2} = 1.281 \]

\[ se(\hat\beta_1) = \sqrt{\frac{\hat\sigma^2}{S_{xx}}} = \sqrt{\frac{1.281}{44.99}} = 0.169 \qquad t = \frac{1.396}{0.169} = 8.27 \qquad R^2 = \frac{SS_R}{S_{yy}} = 0.895 \]

איך קוראים את הפלט

  • Estimate: המקדמים. כל אלף בקשות נוספות בדקה מעלות את ניצולת המעבד ב-1.4 נקודות אחוז בממוצע
  • Std. Error: שגיאת התקן של כל מקדם, \(se(\hat\beta_j)\)
  • t value ו-Pr(>|t|): מבחן \(H_0: \beta_j = 0\), עם \(t = \hat\beta_j / se(\hat\beta_j)\) ו-\(n - 2 = 8\) דרגות חופש. לשיפוע \(p = 0.00003\), ולכן דוחים: הקשר לא מקרי
  • Residual standard error: \(\hat\sigma = \sqrt{MS_E} = 1.13\). זו הסטייה הטיפוסית של תצפית מהקו, ביחידות של \(Y\)
  • Multiple R-squared: 89.5% מהשונות בניצולת המעבד מוסברים על ידי העומס
  • F-statistic: מבחן לכל המודל. ברגרסיה פשוטה \(F = t^2\): \(8.27^2 = 68.4\)

לשאול את הכיתה: למה החותך לא מובהק, ולמה שגיאת התקן שלו כל כך גדולה (2.3)? זה מוביל לשקף הבא.

מה עושים עם החותך? מירכוז (Centering)

החותך הוא הניצולת הצפויה כש-\(x = 0\), הרחק מטווח הנתונים (10 עד 17). לכן השונות שלו גדולה:

\[ V(\hat\beta_0) = \sigma^2 \left[\frac{1}{n} + \frac{\bar x^2}{S_{xx}}\right] \]

אם מחסירים מ-\(x\) את הממוצע שלו, \(\bar x = 0\), והחותך הופך ל-\(\bar y\): הניצולת הצפויה בעומס הממוצע.

פירוק השונות וטבלת ANOVA

\[ \underbrace{\sum_{i}(y_i - \bar y)^2}_{SS_T} = \underbrace{\sum_{i}(\hat y_i - \bar y)^2}_{SS_R} + \underbrace{\sum_{i}(y_i - \hat y_i)^2}_{SS_E} \]

מקור סכום ריבועים דרגות חופש ממוצע ריבועים \(F\)
רגרסיה \(SS_R\) \(1\) \(MS_R = SS_R / 1\) \(MS_R / MS_E\)
שגיאה \(SS_E\) \(n - 2\) \(MS_E = SS_E / (n-2)\)
סך הכול \(SS_T\) \(n - 1\) 
sm.stats.anova_lm(fit_cpu, typ=1)

מקדם המתאם המרובה: \(R^2 = SS_R / SS_T = 87.66 / 97.91 = 0.895\)

שני הרכיבים אי-שליליים, ולכן תמיד \(0 \le R^2 \le 1\).

רגרסיה לינארית מרובה (Multiple linear regression)

השאלה: מה קובע את זמן התגובה של מודל שפה?

חברה משתמשת ב-API של מודל שפה, בשלושה גדלים: small, medium ו-large. המשתמשים מתלוננים על המתנה ארוכה.

השאלות:

  • כמה זמן מוסיף כל טוקן (token) בתשובה? וכל אלף טוקנים בקלט?
  • האם מודל השפה הגדול עצמו איטי יותר, או שהוא פשוט כותב תשובות ארוכות יותר?
  • כמה זמן תיקח קריאה עם 2,000 טוקנים בקלט ו-500 בפלט למודל השפה הגדול?

הנתונים: 250 קריאות מהלוגים (נתונים מדומים). לכל קריאה: גודל מודל השפה, מספר הטוקנים בקלט ובפלט, מספר המסמכים שצורפו לפרומפט (RAG), השעה ביום, וזמן התגובה בשניות.

הנתונים

# Own RNG stream, so edits elsewhere in the lecture don't change this example.
# Note: numpy's RNG differs from R's, so exact simulated values differ from the
# R original, but the data-generating recipe (and so the statistical conclusions
# below) is identical.
rng = np.random.default_rng(303)
n_calls = 250
sizes = ["small", "medium", "large"]
median_output = {"small": 250, "medium": 350, "large": 500}      # tokens
sec_per_token = {"small": 0.010, "medium": 0.018, "large": 0.030}

model = pd.Categorical(rng.choice(sizes, n_calls, p=[0.5, 0.3, 0.2]), categories=sizes)
rag_docs = rng.poisson(3, n_calls)                                # documents added to the prompt
input_tokens = np.round(300 + 550 * rag_docs + rng.lognormal(np.log(400), 0.6, n_calls))
output_tokens = np.round([rng.lognormal(np.log(median_output[m]), 0.5) for m in model])
hour = rng.integers(0, 24, n_calls)

llm = pd.DataFrame({
    "model": model, "rag_docs": rag_docs, "input_tokens": input_tokens,
    "output_tokens": output_tokens, "hour": hour,
})
sec_tok = llm.model.map(sec_per_token).astype(float)
llm["latency"] = np.round(0.8 + 0.25 * llm.input_tokens / 1000 +
                           sec_tok * llm.output_tokens + rng.normal(0, 1, n_calls), 2)
llm["input_k"] = llm.input_tokens / 1000

זמן התגובה מול אורך התשובה

המודל

\[ Y_i = \beta_0 + \beta_1 x_{i1} + \beta_2 x_{i2} + \dots + \beta_k x_{ik} + \varepsilon_i \qquad \varepsilon_i \sim N(0, \sigma^2) \]

  • אותן הנחות כמו ברגרסיה פשוטה, עם \(k\) משתנים מסבירים (predictors)
  • הפרשנות של \(\beta_j\): השינוי בתוחלת של \(Y\) כש-\(x_j\) עולה ביחידה אחת, וכל שאר המשתנים במודל נשארים קבועים
  • “לינארי” פירושו לינארי בפרמטרים \(\beta\). אפשר להכניס \(x^2\), \(\log x\) או מכפלה \(x_1 x_2\), והמודל עדיין לינארי

נתחיל משני משתנים מסבירים: הטוקנים בקלט (באלפים) והטוקנים בפלט.

רישום מטריציוני (Matrix form)

\[ \mathbf{y} = X\boldsymbol\beta + \boldsymbol\varepsilon \qquad X = \begin{pmatrix} 1 & x_{11} & \cdots & x_{1k} \\ \vdots & \vdots & & \vdots \\ 1 & x_{n1} & \cdots & x_{nk} \end{pmatrix}_{n \times (k+1)} \]

ממזערים את \(L(\boldsymbol\beta) = (\mathbf{y} - X\boldsymbol\beta)'(\mathbf{y} - X\boldsymbol\beta)\). הנגזרת היא \(-2X'\mathbf{y} + 2X'X\boldsymbol\beta\), ומשווים אותה לאפס:

\[ X'X\hat{\boldsymbol\beta} = X'\mathbf{y} \quad\Longrightarrow\quad \hat{\boldsymbol\beta} = (X'X)^{-1}X'\mathbf{y} \]

  • העמודה של אחדות ב-\(X\) היא החותך
  • צריך ש-\(X'X\) תהיה הפיכה: אף משתנה לא יכול להיות צירוף לינארי מדויק של האחרים
X = sm.add_constant(llm[["input_k", "output_tokens"]]).to_numpy()  # adds the column of ones
y = llm.latency.to_numpy()
np.linalg.solve(X.T @ X, X.T @ y)                                   # same as fit2.params
array([-2.44920495,  0.24828987,  0.02758599])

תכונות האומדים

  • חסרי הטיה: \(E(\hat{\boldsymbol\beta}) = \boldsymbol\beta\)
  • מטריצת השונויות: \(V(\hat{\boldsymbol\beta}) = \sigma^2 (X'X)^{-1}\). נסמן \(C = (X'X)^{-1}\)
  • אומד ל-\(\sigma^2\): \(\hat\sigma^2 = MS_E = \dfrac{SS_E}{n - k - 1}\). מאבדים דרגת חופש על כל מקדם, כולל החותך

\[ se(\hat\beta_j) = \sqrt{\hat\sigma^2 C_{jj}} \qquad t = \frac{\hat\beta_j}{se(\hat\beta_j)} \sim t_{n-k-1} \qquad \hat\beta_j \pm t_{1-\alpha/2,\, n-k-1} \cdot se(\hat\beta_j) \]

sigma2_hat = (fit2.resid ** 2).sum() / (X.shape[0] - X.shape[1])  # SSE / (n - k - 1)
np.sqrt(np.diag(sigma2_hat * np.linalg.inv(X.T @ X)))              # = "std err" in summary()
array([0.62964118, 0.21145165, 0.00085701])

מבחני השערות במודל המרובה

מבחן F לכל המודל

\[ H_0: \beta_1 = \beta_2 = \dots = \beta_k = 0 \qquad H_1: \text{לפחות מקדם אחד שונה מאפס} \]

מקור סכום ריבועים דרגות חופש ממוצע ריבועים \(F\)
רגרסיה \(SS_R\) \(k\) \(MS_R = SS_R / k\) \(MS_R / MS_E\)
שגיאה \(SS_E\) \(n - k - 1\) \(MS_E = SS_E / (n-k-1)\)
סך הכול \(SS_T\) \(n - 1\)

דוחים את \(H_0\) אם \(F > F_{1-\alpha;\, k,\, n-k-1}\).

  • דחייה אומרת רק שלפחות משתנה אחד עוזר. היא לא אומרת איזה
  • מבחני ה-t בודקים כל מקדם בנוכחות כל השאר. משתנה יכול להיות לא מובהק לבד, ובכל זאת חשוב

\(R^2\) ו-\(R^2\) מתוקן (Adjusted R²)

\[ R^2 = \frac{SS_R}{SS_T} = 1 - \frac{SS_E}{SS_T} \qquad R^2_{adj} = 1 - \frac{SS_E / (n - k - 1)}{SS_T / (n - 1)} = 1 - (1 - R^2)\frac{n - 1}{n - k - 1} \]

  • הבעיה של \(R^2\): הוא אף פעם לא יורד כשמוסיפים משתנה, גם אם המשתנה הוא רעש טהור
  • \(R^2\) המתוקן “מעניש” על כל משתנה נוסף. הוא עולה רק אם המשתנה מקטין את \(MS_E\). למקסם אותו זה כמו למזער את \(MS_E\)

משתנים קטגוריים (Categorical variables)

משתני דמה (Dummy variables)

למשתנה קטגורי עם \(m\) רמות מוסיפים \(m - 1\) משתני דמה (אינדיקטורים). רמה אחת היא רמת הבסיס (reference level), ולה אין משתנה משלה.

\[ D_{medium} = \begin{cases} 1 & \text{medium} \\ 0 & \text{אחרת} \end{cases} \qquad D_{large} = \begin{cases} 1 & \text{large} \\ 0 & \text{אחרת} \end{cases} \]

\[ Y = \beta_0 + \beta_1 x_{input} + \beta_2 x_{output} + \beta_3 D_{medium} + \beta_4 D_{large} + \varepsilon \]

  • \(\beta_4\): בכמה קריאה למודל השפה הגדול איטית יותר מקריאה למודל השפה הקטן, באותו מספר טוקנים
  • למה לא \(m\) משתנים? כי אז \(D_{small} + D_{medium} + D_{large} = 1\), בדיוק כמו עמודת החותך, ו-\(X'X\) לא הפיכה
  • R יוצר את משתני הדמה בעצמו מכל factor. רמת הבסיס היא הרמה הראשונה (levels)

מבחן F חלקי (Partial F test)

השאלה: האם גודל מודל השפה משפיע בכלל? זו השערה על שני מקדמים יחד, \(H_0: \beta_3 = \beta_4 = 0\). אי אפשר לענות עליה עם שני מבחני t נפרדים.

משווים בין המודל המלא (full) לבין המודל המצומצם (reduced), שבו \(H_0\) נכונה:

\[ F = \frac{(SS_E^{R} - SS_E^{F}) / q}{SS_E^{F} / (n - k - 1)} \sim F_{q,\; n-k-1} \]

\(q\) הוא מספר המקדמים שנבדקים, ו-\(k\) הוא מספר המשתנים במודל המלא.

  • RSS: סכום ריבועי השגיאות (\(SS_E\)) של כל מודל. משתני הדמה הורידו אותו מ-2656 ל-1025
  • Df = 2: הוספנו \(q = 2\) מקדמים
  • בחישוב ידני (דוחים את \(H_0\): גודל מודל השפה משפיע):

\[ F = \frac{(2656 - 1025) / 2}{1025 / 245} = 195 \]

  • מבחן F לכל המודל הוא מקרה פרטי: המודל המצומצם הוא מודל עם חותך בלבד

בחירת משתנים (Variable selection)

שלוש גישות

  • קדימה (Forward): מתחילים ממודל בלי משתנים. בכל צעד מוסיפים את המשתנה שמשפר את הקריטריון הכי הרבה. עוצרים כשאף הוספה לא משפרת
  • אחורה (Backward): מתחילים מכל המשתנים. בכל צעד מוציאים את המשתנה שתורם הכי מעט, כל עוד ההוצאה לא פוגעת בקריטריון
  • בצעדים (Stepwise): כמו קדימה, אבל אחרי כל הוספה בודקים אם כדאי להוציא משתנה שכבר נכנס

קריטריונים נפוצים: \(R^2_{adj}\), ה-p-value של מבחן F חלקי, או AIC (מדד שמאזן בין טיב ההתאמה למספר הפרמטרים. קטן יותר = טוב יותר)

# statsmodels has no built-in step(); a small bidirectional-by-AIC search, like R's step().
def stepwise_aic(data, response, all_terms, start_terms):
    def fit_of(terms):
        rhs = " + ".join(terms) if terms else "1"
        return smf.ols(f"{response} ~ {rhs}", data=data).fit()

    current = list(start_terms)
    current_aic = fit_of(current).aic
    improved = True
    while improved:
        improved = False
        candidates = []
        for t in all_terms:
            if t not in current:
                candidates.append(("add", t, current + [t]))
        for t in current:
            candidates.append(("drop", t, [x for x in current if x != t]))
        best = None
        for action, term, terms in candidates:
            aic = fit_of(terms).aic
            if best is None or aic < best[0]:
                best = (aic, action, term, terms)
        if best is not None and best[0] < current_aic:
            current_aic, _, _, current = best
            improved = True
    return fit_of(current), current

all_terms = ["input_k", "rag_docs", "hour", "output_tokens", "C(model)", "output_tokens:C(model)"]

  • עדיף: לבנות את המודל מתוך הבנה של המנגנון, ולבדוק אותו על נתונים שלא השתתפו בבנייתו. בפועל מחלקים את הנתונים לשני חלקים: סט אימון (train) שעליו בוחרים ואומדים את המודל, וסט בדיקה (test) שעליו בודקים את החיזוי. בקורס בלמידת מכונה תלמדו על כך יותר

חיזוי (Prediction)

רווח סמך מול רווח חיזוי

לנקודה חדשה \(\mathbf{x}_0 = (1, x_{01}, \dots, x_{0k})'\), החיזוי הוא \(\hat y_0 = \mathbf{x}_0'\hat{\boldsymbol\beta}\). יש שתי שאלות שונות:

  • רווח סמך (confidence interval): איפה התוחלת \(E(Y \mid \mathbf{x}_0)\), זמן התגובה הממוצע של כל הקריאות האלה?
  • רווח חיזוי (prediction interval): איפה תיפול קריאה בודדת חדשה?

\[ \text{CI:}\;\; \hat y_0 \pm t_{1-\alpha/2,\, n-k-1}\sqrt{\hat\sigma^2\, \mathbf{x}_0'(X'X)^{-1}\mathbf{x}_0} \qquad \text{PI:}\;\; \hat y_0 \pm t_{1-\alpha/2,\, n-k-1}\sqrt{\hat\sigma^2 \left(1 + \mathbf{x}_0'(X'X)^{-1}\mathbf{x}_0\right)} \]

ה-1 הנוסף ברווח החיזוי הוא השונות של התצפית החדשה עצמה. גם עם אינסוף נתונים הוא לא נעלם.

ברגרסיה פשוטה, \(\mathbf{x}_0'(X'X)^{-1}\mathbf{x}_0 = \dfrac{1}{n} + \dfrac{(x_0 - \bar x)^2}{S_{xx}}\): הרווחים צרים ביותר ב-\(\bar x\) ומתרחבים ככל שמתרחקים ממנו.

חזרה לשאלה: כמה זמן תיקח הקריאה?

2,000 טוקנים בקלט, 500 בפלט, מודל השפה הגדול:

חמש מלכודות

  1. אקסטרפולציה: לפי מודל המעבד, ניצולת של 80% תגיע בעומס של כ-57 אלף בקשות בדקה. אבל מדדנו רק בין 10 ל-17. מעבדים בעומס גבוה מתנהגים אחרת (תורים, throttling), והמודל לא יודע על זה כלום
  2. מתאם אינו סיבתיות: נתוני הלוגים הם תצפיתיים. אם משתמשים בוחרים במודל השפה הגדול למשימות קשות, ייתכן שגם משהו אחר במשימות האלה מאט אותן. כדי לדעת בוודאות, צריך ניסוי (על כך בהרצאה על תכנון ניסויים)
  3. \(R^2\) גבוה אינו הוכחה: הוא תמיד עולה כשמוסיפים משתנים. משווים מודלים לפי \(R^2_{adj}\), מבחן F חלקי, או ביצועים על נתונים חדשים
  4. מולטיקולינאריות: מקדמים לא יציבים ושגיאות תקן גדולות, אף שהחיזוי בסדר
  5. מודל שגוי מסתיר אפקטים: input_k נראה חסר השפעה עד שהוספנו את גודל מודל השפה והאינטראקציה. תמיד מסתכלים על השאריות
